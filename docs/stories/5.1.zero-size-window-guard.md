# Story 5.1: Zero-size window guard

## Status

Done

## Story

**As a** visitor whose page loads in a hidden or zero-size window (a
background tab, an iframe, a collapsed pane),
**I want** the scene to start normally once it's shown,
**so that** the man is never missing and the page never throws errors.

## Acceptance criteria

1. If the view is computed at 0 × 0, 0 × h or w × 0, the last good view is
   kept. Nothing is divided by zero.
2. After such a start, once the window has a real size, the man has a finite
   position and no NaN reaches the canvas, including the contact shadow's
   radial gradient.
3. Existing behaviour at real sizes is unchanged (full suite passes).

## Tasks / subtasks

- [x] Guard `Scene.computeView` against non-positive sizes (AC 1)
- [x] Regression test: start at 0 × 0, 0 × 900 and 1280 × 0, then show at
  1280 × 720 (AC 2)
- [x] Full suite and build (AC 3)

## Dev notes

- **Reported by:** the greeting chat (story 2.2 work). At a 0 px window,
  `manX` was NaN and `drawContactShadows` threw in `createRadialGradient`.
- **Cause:**
  - The mobile fix (commit b46fe04) added an early
    `scene.computeView(p.width, p.height)` in p5 `setup`, which bypassed the
    zero-size guard in `render()`.
  - At 0 × 0, `w = 0/0` gives NaN, so the man was placed at NaN.
  - Later, `changedWidth` compared against NaN (always false), so his
    position was never repaired.
- **Fix:** `computeView` returns early unless both sizes are positive.

### Testing

`tests/scene.test.mjs`, test "a 0 x 0 window at start-up …". It fails
without the fix (verified) and passes with it.
