# Story 2.8: The bubble flashed on page load (bug)

## Status

Done

## Story

**As a** visitor,
**I don't want** to see Tony's introduction flash in the top-left corner
as the page loads,
**so that** the scene opens cleanly and the bubble is only ever a response
to meeting him.

## The bug

- **Reported by the owner** on `npm run dev` (localhost:5173). The bubble's
  text showed in the top-left corner for less than a second after load,
  fading out.
- **Cause:**
  - The bubble's markup is in `index.html`. In dev, Vite injects
    `main.css` from JavaScript, after the HTML is already drawn.
  - So the bubble rendered unstyled and fully visible. When the CSS
    arrived, its `opacity` transition (0.8 s) faded it out, instead of it
    starting hidden.
- **Measured** with a headless frame recorder: visible from about 50 ms
  (no stylesheets yet), fading until about 870 ms.
- **Live site:** not affected, because the built page loads the stylesheet
  as a `<link>` in the page head before the first paint ("never visible"
  on the live URL). It was still fragile: a slow stylesheet could cause the
  same flash.

## Acceptance criteria

1. On load, the bubble is never drawn before the greeting, in dev and in
   the built site.
2. When he greets, the bubble appears, reveals, holds and fades as before.
3. Tests and the build pass.

## Fix

- `index.html`: `#bubble` starts with the `hidden` attribute, so it's never
  rendered before the styles arrive.
- `src/bubble.js`: `createBubble` sets `el.hidden = false`. The CSS is in
  place by then, so the bubble starts from its styled, invisible state and
  no transition plays.
