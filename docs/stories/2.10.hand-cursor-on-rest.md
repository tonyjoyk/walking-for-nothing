# Story 2.10: The hand cursor didn't show when the pointer came to rest (bug)

## Status

Done

## Report

The owner noticed that the hand cursor over the man (story 2.9) seemed to
have gone, and asked whether another change had overwritten it.

## Findings

- **Nothing was overwritten.** The CSS rule (`html.on-man`) and the toggle
  in `main.js` are intact on `main`, on the live site, and in both other
  sessions' worktrees (lightning, sound credits). Neither of those sessions'
  edits touches the cursor or hover code.
- **Cause:**
  - The class was only toggled in the animation frame, after the
    `pointermove`.
  - Browsers redraw the cursor only when the mouse moves.
  - So when a visitor moved onto him and stopped, the class arrived just
    after the last movement, and the arrow stayed until they moved again.
  - Test browsers report the computed cursor, but never draw it, so the
    earlier QA couldn't see this.
- **Proof** (headless Chrome, with the animation loop stopped so nothing
  but the event can act), after one real mouse movement onto him:
  - **Before the fix:** the class is still `""`, so no hand.
  - **After the fix:** `on-man`, so the hand shows on that same movement.

## Fix

`updateHandCursor()` in `main.js` runs:
- inside the `pointermove` handler, so the movement that reaches him shows
  the hand;
- when the pointer leaves the page;
- each frame, so the hand keeps in step when he walks under a still
  pointer.

## Acceptance criteria

1. Moving the pointer onto him shows the hand on that same movement.
2. The other cases behave as in story 2.9: no hand off him or over the
   bubble, and none on touch.
3. Tests and the build pass.
